### 2. Что должно получиться

**`src/DoomPB.pb`**

- Чистый консольный минимальный исполняемый файл, написанный на PureBasic 6.41.
- Включи `EnableExplicit` и явные объявления переменных.
- Команда `DoomPB --version` печатает `DoomPB 0.0.1` и корректно завершается.
- Команда `DoomPB --help` выводит краткую справку и завершается успешно.
- Запуск без аргументов **не требует `DOOM.WAD`** и не падает; сообщает, что WAD Loader ещё не реализован.
- Не заявляй, что программа уже читает WAD или запускает Doom; не реализуй никакой WAD-парсер на этапе M0.
- Проверяй неизвестные параметры и возвращай осмысленный код завершения; минимальное поведение важнее «универсального CLI-фреймворка».

**`scripts/build.ps1` и `scripts/build.sh`**

- Из любой текущей рабочей директории надёжно определяют корень проекта относительно расположения самих скриптов.
- Находят компилятор через `PB_COMPILER` или `PATH`. Разрешено локальное обнаружение установки, но абсолютные пути конкретного разработчика **не записывать в репозиторий**.
- Поддерживают как **проверку синтаксиса**, так и **полную сборку**. Предложенный интерфейс: Windows `build.ps1 -Check`, Linux `build.sh --check` (обычный запуск = полная сборка).
- Для проверки используют `pbcompiler src/DoomPB.pb --check`; для сборки `pbcompiler src/DoomPB.pb --output ...` (с учётом местоположения файлов и платформы).
- Создают `build/` до записи бинарника и сохраняют код возврата компилятора; при ошибке возвращают ненулевой статус. На Windows результат — `build/DoomPB.exe`, на Linux — `build/DoomPB`.
- Правильно обрабатывают пробелы в путях к компилятору и файлам.
- Никаких скачиваний бинарных зависимостей, автоматической установки PureBasic или скрытого исполнения непроверенных скриптов.

**`scripts/test.ps1` и `scripts/test.sh`**

- Выполняют синтаксическую проверку и сборку, затем проверяют `--version`, `--help`, запуск без аргументов и ожидаемые коды возврата.
- Проверки должны запускать **реальный собранный бинарник**; не выдавай статический текст за результаты тестов.
- Возвращают ненулевой exit code при любой ошибке.
- Работают без коммерческого IWAD и без графического дисплея.
- Если ОС/компилятор недоступны, не имитируй прохождение соответствующей платформы.

**`README.md`, `LICENSE`, `.gitignore`, `PORTING_NOTES.md`**

- README кратко описывает цель DoomPB, статус `0.0.1` (пока каркас), требования PureBasic 6.41, команды сборки/тестов, лицензирование и необходимость **собственного легально приобретённого IWAD в будущем**.
- `LICENSE` содержит полный официальный текст GNU GPL version 2; не сокращай и не пересказывай лицензию. Если текст нельзя достоверно получить, честно отметь это как блокер.
- `.gitignore` исключает `*.wad`/`*.WAD` (включая `DOOM.WAD`), `local-data/`, `data/`, `build/`, `dist/`, `*.exe`, `*.dll`, `*.so`, временные файлы и секреты. Позднее синтетические fixtures будут разрешаться узкими исключениями, если потребуется.
- `PORTING_NOTES.md` описывает только реально проверенные обстоятельства и не содержит придуманного commit SHA исходников `id-Software/DOOM`.
- При работе с любыми чужими файлами сохраняй copyright notices и их лицензии. Не добавляй коммерческие игровые данные или извлечённые изображения/звуки.

### 3. Ограничения по действиям

- **Не** реализуй `WAD.pbi`, `PLAYPAL`, `TITLEPIC`, рендерер или gameplay: это M1 и дальше.
- **Не** изменяй `AGENTS.md` и `docs/DEVELOPMENT_PLAN.md` без конкретной необходимости и согласования.
- **Не** устанавливай сторонние зависимости и не подменяй PureBasic C/C++ реализацией.
- **Не** создавай GitHub remote, не выполняй `git push`, `git commit`, не публикуй release и не меняй настройки репозитория. Если Git ещё не инициализирован, сначала сообщи об этом; локальная инициализация допустима только при отсутствии риска для существующих данных и с явно описанным действием.
- **Не** применяй `git reset --hard`, `git clean -fd`, force-push, массовые удаления или переформатирование чужого кода.
- Не читай и не передавай содержимое коммерческого `DOOM.WAD` во внешние API: на этапе M0 он вообще не нужен.

### 4. Проверки и критерии завершения

Выполни на доступной платформе в следующем порядке:

1. Реальная проверка версии PureBasic 6.41.
2. Реальная проверка синтаксиса через скрипт.
3. Реальная сборка `.exe`/Linux binary через скрипт.
4. Реальный smoke test: `--version`, `--help`, запуск без аргументов (без IWAD).
5. `git diff --check`, `git diff --stat`, `git diff` и `git status --short` (для неотслеживаемых файлов дополнительно покажи перечень).
6. Убедись, что WAD-файлы и `build/` не попадут в коммит (при желании `git check-ignore`).

**M0 можно считать завершённым**, только если реальная сборка запускается, печатает версию и корректно завершается. Не утверждай, что Windows и Linux проверены, если тестировал только одну платформу.
